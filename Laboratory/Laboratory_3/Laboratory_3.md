**2.3. Для чого потрібен Amazon Budgets? Які є варіанти налаштувань? (на базі другого відео).**  
<br>
**Amazon Budgets** — cервіс для контролю та моніторингу витрат і використання ресурсів хмари з метою запобігання непередбаченим фінансовим списанням.
<br>  
**Варіанти налаштувань:**
* Zero Spend Budget: Бюджет нульових витрат (надсилає сповіщення при перевищенні суми \$0.01, тобто при виході за межі безкоштовного тарифу Free Tier).
* Monthly Cost Budget: Фіксований щомісячний грошовий ліміт (наприклад, \$10/місяць) із налаштуванням порогів сповіщення (наприклад, при досягненні 80% від суми).
* Usage Budget: Моніторинг вичерпання годин використання конкретних ресурсів (наприклад, 750 годин EC2).

**2.4. Яке призначення IAM policy? Як налаштувати дозволи для різних користувачів? (на базі другого відео).**
<br>  
**IAM Policy** — це JSON-документ, який чітко визначає списки дозволених (`Allow`) або заборонених (`Deny`) дій над конкретними ресурсами AWS.
Згідно з кращими практиками безпеки (Principle of Least Privilege), політики прив'язуються до груп користувачів (IAM Groups) або ролей (IAM Roles), 
а не призначаються кожному користувачу окремо.

---

<br>

**2.5. Які варіанти додавання IAM policy є при створенні нового користувача, опишіть коротко кожен з них (на базі другого відео).**
1.  **Add user to group** (додати користувача до групи): Надає користувачу всі політики та права, які вже призначені цій групі (найбільш рекомендований спосіб).
2.  **Copy permissions** (копіювати дозволи): Скопіювати повний набір прав від уже існуючого користувача.
3.  **Attach policies directly** (прикріпити політики напряму): Пряме призначення керованих політик (AWS Managed або Customer Managed) безпосередньо акаунту користувача.

---

<br>

**2.6. Опишіть як можна писати і застосовувати політики для контролю доступу через IAM Policies (на базі третього відео).**  
<br>
Політика складається з блоку `Statement`, який містить:
*   `Effect`: `Allow` або `Deny`.
*   `Action`: конкретні API-команди сервісів (наприклад, `s3:GetObject`, `ec2:RunInstances`).
*   `Resource`: ARN-ідентифікатор конкретного ресурсу, на який поширюється дія.
*   `Condition` (опціонально): додаткові умови (наприклад, запит тільки з визначеної IP-адреси або при активованому MFA).

---

<br>

**2.7. Опишіть як перемикатися між ролями для безпечного доступу до різних ресурсів за допомогою Switching IAM Roles (на базі третього відео).**
<br>  
Перемикання між ролями дозволяє тимчасово змінити свій контекст безпеки та отримати права іншої IAM Ролі в межах того самого або іншого AWS-акаунта без використання додаткових паролів. Задля цього
у консолі потрібно натиснути на ім'я профілю ➔ обрати **Switch Role** ➔ вказати Account ID, назву ролі (`Role Name`) та обрати колір плашки для ідентифікації.

---

<br>

**2.8. Опишіть як обмежити максимальні дозволи для IAM ролей і користувачів з використанням Permissions Boundary (на базі третього відео).**
<br>  
**Permissions Boundary** — це інструмент керування безпекою, який встановлює «верхню межу» (максимально можливий набір прав) для IAM-користувача або ролі. 
Навіть якщо користувачу додано політику `AdministratorAccess`, він не зможе виконати дію, якщо вона не входить у встановлений Permissions Boundary.

---

<br>

**2.9. Як відстежувати і аналізувати дії користувачів та сервісів в AWS за допомогою CloudTrail (на базі третього відео)?**
<br>  
**AWS CloudTrail** записує та веде аудит усіх подій, дій та API-викликів у консолі, CLI або SDK. У розділі **Event History** 
можна переглядати історію за останні 90 днів: хто саме (користувач/роль), з якої IP-адреси, коли і яку саме операцію створив чи змінив.

---

<br>

**2.10. Яке призначення Policy Simulator, для чого його використовують?**
<br>  
**IAM Policy Simulator** — це інтерактивний інструмент від AWS для тестування та перевірки дійсності створених IAM-політик. Він дозволяє перевірити, чи матиме користувач або роль доступ до конкретної дії до реального застосування змін у продакшн-середовищі.

</blockquote>

### Відповіді на контрольні питання

**<span>1. В чому суть TOTP аутентифікації? Наведіть приклади.</span>**  

Це алгоритм генерації одноразових тимчасових паролів, який базується на спільному секретному ключі та поточному часі (пароль зазвичай змінюється кожні 30 секунд). Пристрій користувача та сервер провайдера синхронно вираховують 6-значний код, що унеможливлює використання перехопленого коду повторно. До прикладів можна віднести Google Authenticator, Authy, Microsoft Authenticator, 1Password, YubiKey.

<br>

**<span>2. Опишіть формат JSON: де він використовується, які його особливості. Чи застосовується цей формат у AWS?</span>**  

JSON (JavaScript Object Notation) — текстовий формат обміну даними, що будується на парах «ключ-значення» та впорядкованих списках. Він є легким для читання людиною та стандартизованим для парсингу програмами. JSON використовується в AWS повсюдно — для опису політики безпеки (IAM Policies), у конфігураціях AWS CloudFormation, для виводу відповідей команд AWS CLI та логування подій у CloudTrail.

<br>

**<span>3. Які є види Amazon API? Коротко опишіть їх.</span>**  

*   **REST API:** Стандартні веб-сервіси на базі HTTP-протоколу з підтримкою повного спектру методів (GET, POST, PUT, DELETE) та стейтлес-архітектурою.
*   **HTTP API:** Полегшена, високопродуктивна та дешевша версія REST API для побудови бессерверних додатків (AWS Lambda).
*   **WebSocket API:** Двостраничні мережеві з'єднання для обміну даними в реальному часі (чати, сповіщення).
*   **AWS Service APIs (Query/JSON/XML APIs):** Низькорівневі внутрішні API-інтерфейси для прямого управління ресурсами AWS через CLI або SDK.

<br>

**<span>4. Як можна встановити AWS CLI під різними операційними системами?</span>**  

*   **Windows:** Завантаження та запуск MSI-інсталятора (`AWSCLIV2.msi`) або через пакетний менеджер `winget install Amazon.AWSCLI`.
*   **macOS:** Завантаження офіційного `.pkg` пакета або через Homebrew: `brew install awscli`.
*   **Linux:** Завантаження zip-архіву через `curl`, його розпакування та запуск скрипта інсталяції: `./aws/install`.

    ```bash
    aws s3 cp document.txt s3://my-unique-bucket-name/
    ```
*   Перегляд списку користувачів IAM:
    ```bash
    aws iam list-users
    ```

### Висновки  

Під час виконання лабораторної роботи було опрацьовано теоретичний та практичний матеріал щодо роботи з провідним світовим хмарним провайдером Amazon Web Services (AWS). Було успішно зареєстровано акаунт AWS Free Tier, налаштовано заходи двофакторної автентифікації (MFA) для захисту Root-акаунта та створено бюджет нульових витрат (Zero Spend Budget) у сервісі AWS Budgets для запобігання непередбаченим витратам. У ході практичних завдань було вивчено роботу з сервісом IAM (створено відповідних користувачів із розмежованими правами), встановлено та сконфігуровано інструмент командного рядка AWS CLI, за допомогою якого було перевірено стан віртуальних машин EC2 та сформовано підсумкову довідку з базових команд управління хмарою.
