<blockquote>
  
**2.1. Для чого призначений сервіс Google Compute Engine (GCE) у складі Google Cloud Platform?**  

Сервіс Google Compute Engine є базовим обчислювальним компонентом категорії IaaS у хмарній екосистемі Google Cloud Platform, призначеним для створення, масшабування та адміністрування віртуальних машин на базі високопродуктивної глобальної інфраструктури Google. Він надає розробникам повний контроль над гостьовими операційними системами Linux та Windows, дозволяючи гнучко налаштовувати кількість віртуальних ядер vCPU, обсяг оперативної пам'яті, типи дискових накопичувачів та мережеві інтерфейси для розгортання як простих веб-додатків, так і складних корпоративних систем чи розподілених обчислювальних кластерів.

---

**2.2. Що таке Machine Images у GCP? Чим відрізняються стандартні образи, надані Google, від користувацьких (Custom Images)?**  

Machine Images у GCP являють собою точні зашифровані шаблони дискових накопичувачів, що містять встановлену операційну систему, системні конфігурації, драйвери та додаткове програмне забезпечення для прискореного створення нових віртуальних машин. Стандартні образи надаються безпосередньо Google та офіційними вендорами через Google Cloud Marketplace і включають чисті, оптимізовані дистрибутиви ОС, такі як Ubuntu, Debian, RHEL чи Windows Server із підтримкою регулярних оновлень безпеки. Натомість користувацькі образи створюються безпосередньо інженерами або адміністраторами компанії на основі знімків існуючих віртуальних машин із заздалегідь передвстановленим корпоративним стеком додатків, внутрішніми сертифікатами та утилітами, зберігаючись у приватному каталозі проєкту для забезпечення стандартизованого деплою інфраструктури.

---

**2.3. Для чого використовуються Persistent Disks у GCP? Які існують типи дисків та у чому їхні відмінності (Standard, Balanced, SSD)?**   

Persistent Disks у Google Cloud Platform являють собою повністю керовані мережеві блокові накопичувачі високої надійності, що підключаються до віртуальних машин Compute Engine і забезпечують незалежне збереження даних навіть після зупинки або видалення самого інстансу. Сервіс пропонує кілька ключових типів дисків: Standard Persistent Disk на основі традиційних магнітних накопичувачів HDD забезпечує найнижчу вартість за гігабайт для послідовних операцій читання/запису та обробки великих масивів даних; Balanced Persistent Disk пропонує оптимальний баланс ціни й продуктивності на базі SSD для більшості загальних робочих навантажень та веб-серверів; а Extreme / SSD Persistent Disk забезпечує максимальну швидкість виконання випадкових операцій вводу-виводу (IOPS) та мінімальну затримку для високонавантажених баз даних та транзакційних систем.

---

**2.4. Що таке Snapshots у Google Cloud? У яких випадках їх доцільно створювати та використовувати?**   

Snapshots у Google Cloud являють собою інкрементні точкові резервні копії вмісту дисків Persistent Disks, які стискаються та зберігаються у високозахищеному об'єктному сховищі Google Cloud Storage з автоматичним розподілом між зонами доступності. Їх доцільно створювати перед виконанням системних оновлень, внесенням критичних змін у конфігураційні файли, розгортанням нових версій програмного коду або для забезпечення регулярного катастрофостійкого резервного копіювання за розкладом. Вони дозволяють у разі аварійного збою миттєво відновити стан диска або використати його як основу для генерації нових віртуальних машин у будь-якому регіоні GCP.

---

**2.5. Перелічіть основні типи віртуальних машин (Machine Types) у GCP. Коли доцільно використовувати кожен тип (e2, n2, n2-highmem, n2-highcpu тощо)?**  

Класифікація екземплярів Google Compute Engine охоплює кілька оптимізованих сімейств: екземпляри загального призначення серії E2 (наприклад, e2-micro, e2-small) та N2 надають збалансовані ресурси vCPU та RAM для малих веб-серверів, середовищ розробки та баз даних середнього розміру, причому e2-micro входить до пільгового ліміту GCP Free Tier; конфігурації n2-highcpu оптимізовані за обчислювальною потужністю процесора і застосовуються для кодування відео, ігрових серверів та високонавантажених обчислень; серія n2-highmem забезпечує збільшений обсяг оперативної пам'яті на кожне ядро для бази даних In-Memory та аналітики Big Data; а спеціалізовані серії A2 та G2 оснащені графічними прискорювачами NVIDIA для завдань машинного навчання, штучного інтелекту та 3D-рендерингу.

---

**2.6. Які дистрибутиви операційних систем доступні у шаблонах Google Cloud Free Tier? Наведіть приклади для сімейств Windows і Linux.**  

У межах ознайомчого тарифу Google Cloud Free Tier користувачам надається широкий вибір базових дистрибутивів Linux, таких як Ubuntu Server 22.04 / 24.04 LTS, Debian 11 / 12 та Rocky Linux, які вимагають мінімальних системних ресурсів і сумісні з конфігурацією e2-micro (0.25–2 vCPU, 1 ГБ RAM) та безкоштовним диском Standard Persistent Disk обсягом до 30 ГБ. Для сімейства Windows підтримуються образи Windows Server 2019 / 2022 Datacenter та Windows Server Core, однак їх створення у межах статусу Free Trial обмежене політикою GCP щодо платного ліцензування Microsoft, що вимагає оновлення підписки (Upgrade to paid billing account) або використання стандартних Linux-дистрибутивів.

---

**2.7. Яке призначення мають Firewall rules у GCP і як вони впливають на доступ до віртуальної машини?**   

Правила брандмауера Firewall rules у мережі Virtual Private Cloud (VPC) GCP виступають глобальним розподіленим мережевим екранним бар'єром, який контролює вхідний (Ingress) та вихідний (Egress) мережевий трафік на рівні кожної віртуальної машини незалежно від її гостьової ОС. За замовчуванням у GCP весь вхідний трафік із мережі Інтернет повністю заблоковано, за винятком авторизованого протоколу SSH через утиліти gcloud, тому створення відповідних правил дозволу (наприклад, дозволити порт 80 для HTTP, 443 для HTTPS або 3389 для RDP) є обов'язковою умовою для забезпечення публічного доступу користувачів до розгорнутих веб-серверів чи графічних столів.

---

**2.8. У чому різниця між підключенням до віртуальної машини через SSH та через RDP? У яких випадках використовується кожен спосіб?**  

Підключення через SSH являє собою захищений текстовий консольний протокол адміністрування, який використовує асиметричне криптографічне шифрування через порти за замовчуванням і застосовується для управління серверами сімейства Linux без витрат ресурсів на графічну оболонку. Натомість RDP є графічним протоколом віддаленого робочого столу, який транслює відеопотік інтерфейсу та команд введення миші/клавіатури через порт 3389 для адміністрування ОС Windows Server. SSH є основним стандартом для автоматизованого CI/CD, скриптування та управління веб-серверами, тоді як RDP використовується для системного адміністрування програм із графічним інтерфейсом.

</blockquote>

<span>9. Аналіз причин обмеження та механізм підключення через RDP:</span>
Дана помилка виникає через сувору політику захисту від зловживань та особливості ліцензування комерційного програмного забезпечення Microsoft у хмарі GCP. Провайдер Google Cloud блокує генерацію інстансів Windows Server для ознайомчих акаунтів Free Trial ($300 trial credits) до моменту оновлення білінг-профілю (Upgrade to paid billing account).

У разі активації платного акаунта або стандартної інфраструктури підключення та адміністрування Windows Server здійснюється за наступним алгоритмом:
1. Генерація пароля адміністратора через утиліти GCP:
```bash
gcloud compute reset-windows-password windows-dimarudenko --zone=us-central1-a --user=azureuser
```
2. Підключення через системну утиліту `mstsc.exe` (Remote Desktop Connection) за External IP та створеним паролем.
3. Перейменування комп'ютера у системних налаштуваннях `Settings -> System -> About` на `WSERVER-Руденко_Д`.
4. Видалення ресурсів після завершення роботи:
```bash
gcloud compute instances delete windows-dimarudenko --zone=us-central1-a --quiet
```

### Відповіді на контрольні питання
**<span>1. Яку роль відіграють SSH-ключі та паролі при підключенні до віртуальних машин у GCP?</span>** <br>
Криптографічні SSH-ключі використовуються для криптографічно захищеної асиметричної автентифікації при підключенні до віртуальних машин сімейства Linux, де публічний ключ автоматично імпортується у метадані інстансу утилітами gcloud, а приватний ключ зберігається у клієнта, що повністю унеможливлює перехоплення паролів або атаки перебором Brute-Force. Паролі облікових записів адміністратора використовуються як первинний фактор автентифікації при вході у графічне середовище Windows Server за протоколом RDP, де у GCP застосовується механізм динамічної генерації пароля через функцію Set Windows Password для кожного нового інстансу.

---

**<span>2. Яка команда використовується для підключення до Linux-віртуальної машини через gcloud CLI?</span>** <br>
Для підключення до віртуальної машини Linux через утиліту gcloud CLI використовується команда `gcloud compute ssh <назва_ВМ> --zone=<назва_зони>`, яка автоматично генерує тимчасову пару SSH-ключів, додає публічний ключ у метадані проєкту GCP та відкриває інтерактивну термінальну сесію до екземпляра без необхідності ручного налаштування файлів ключів.

---

**<span>3. Які способи підключення доступні для Linux-VM у GCP?</span>** <br>
Для підключення до Linux-машин у GCP доступні такі методи: інтерактивна кнопка SSH (Open in browser window) безпосередньо в консолі GCP Portal за допомогою браузерного SSH-клієнта; командний рядок gcloud CLI за допомогою команди `gcloud compute ssh`; стандартний OpenSSH клієнт у локальному терміналі за допомогою власної пари ключів та External IP; підключення через сервіс Identity-Aware Proxy (IAP) SSH без використання публічної IP-адреси; а також текстова інструментальна консоль Serial Console для відновлення доступу при мережевих збоях.

---

**<span>4. Як можна підключитися до Windows-віртуальної машини у GCP?</span>** <br>
Для підключення до віртуальної машини Windows у GCP використовується графічний протокол RDP через клієнтські утиліти Remote Desktop Connection (mstsc.exe) за зовнішньою IP-адресою та авторизаційними даними, створеними за допомогою функції Set Windows Password у веб-консолі GCP, або через консоль Cloud Console RDP у браузері, чи із застосуванням шлюзу Identity-Aware Proxy (IAP) RDP для захищеного доступу без відкриття порту 3389 у відкриту мережу Інтернет.

---

**<span>5. У чому полягає різниця між станами Stop і Delete для віртуальної машини?</span>** <br>
Операція Stop зупиняє виконання процесів та повністю вивільняє обчислювальні ресурси vCPU і RAM хост-сервера, внаслідок чого припиняється нарахування плати за процесорний час, однак при цьому диски Persistent Disks та збережені дані залишаються у хмарі й продовжують тарифікуватися за обсяг збереженої інформації до моменту повторного запуску машини. Операція Delete повністю й безповоротно видаляє конфігурацію віртуальної машини, її мережеві інтерфейси та зв'язані диски з хмарної інфраструктури, що призводить до повного припинення будь-якої тарифікації та остаточного очищення ресурсів.

---

**<span>6. Для чого використовується Startup script під час створення VM?</span>** <br>
Startup script використовується для автоматизації початкового конфігурування віртуальної машини під час її першого завантаження або кожного повторного запуску, дозволяючи без ручного втручання адміністратора виконувати скрипти ініціалізації cloud-init або bash, оновлювати пакети операційної системи, встановлювати необхідний стек веб-серверів та баз даних, завантажувати програмний код із репозиторіїв та налаштовувати системні служби.

---

**<span>7. Як у GCP можна дозволити або заборонити вхідний трафік до віртуальної машини?</span>** <br>
Керування вхідним трафіком у GCP здійснюється за допомогою правил брандмауера VPC Firewall Rules, де можна створювати правила типу Allow або Deny, вказуючи конкретні протоколи (TCP, UDP, ICMP), мережеві порти, джерела IP-адрес та мережеві теги target tags, а також безпосередньо під час створення віртуальної машини у веб-інтерфейсі шляхом встановлення прапорців Allow HTTP/HTTPS traffic.

### Висновки
У ході виконання лабораторної роботи №9 було детально опановано практичні навички розгортання, мережевого конфігурування та адміністрування віртуальних машин у хмарному середовищі Google Cloud Platform на базі Compute Engine. Під час практичних завдань було успішно розгорнуто Linux-сервер на ОС Ubuntu 22.04 LTS із використанням Startup script для автоматичної інсталяції Nginx, налаштовано правила брандмауера VPC Firewall для дозволу трафіку за портами HTTP та HTTPS, проведено SSH-підключення за допомогою інструменту gcloud CLI та оновлено конфігураційні файли з інформацією про студентський колектив групи РПЗ-34. Крім того, було досліджено офіційні обмеження ознайомчого тарифу GCP Free Trial щодо розгортання Windows Server ВМ (помилка `VMs based on Windows Server images can't be created while in the Free Trial program`), вивчено принципи платних ліцензій Microsoft у хмарі, проаналізовано синтаксис налаштування RDP-доступу та відпрацьовано команди зупинки gcloud compute instances stop і повного видалення gcloud compute instances delete для дотримання принципу Zero Cost у хмарній інфраструктурі.
