**2.1. Що таке віртуальна машина та які особливості їх реалізації у Google Compute Engine?**  

**Віртуальна машина (Virtual Machine, VM)** — це програмно емульований комп'ютерний комплекс, який функціонує на базі фізичного серверного обладнання під контролем гіпервізора, маючи виділені віртуальні процесори (vCPU), оперативну пам'ять, віртуальні накопичувачі та мережеві інтерфейси. Вона реалізує модель обслуговування **IaaS (Infrastructure as a Service)**, надаючи користувачеві повний адміністративний контроль над гостьовою операційною системою (Linux або Windows) та встановленим стеком ПЗ.

---

**2.2. Які можливості надає Google App Engine для розгортання веб-застосунків?**  

**Google App Engine (GAE)** — це повністю керована **PaaS-платформа (Platform as a Service)** для прискореної розробки, розгортання та автоматичного масштабування веб-додатків і мікросервісів у глобальній інфраструктурі Google без необхідності конфігурувати віртуальні машини чи мережеве обладнання.

---

**2.3. Які основні кроки створення App Engine-додатка через Google Cloud Console?**  

Створення та деплой веб-додатка в середовищі Google App Engine здійснюється за наступними послідовними етапами:
1. **Створення та вибір проєкту:** У Google Cloud Console відкрити верхню панель вибору проєктів та створити новий проєкт.
2. **Ініціалізація сервісу App Engine:** У боковому навігаційному меню знайти розділ **App Engine** та натиснути кнопку **Create Application**.

Управління доступом у Google Cloud Platform реалізовано за допомогою системи **Cloud IAM (Identity and Access Management)**, яка забезпечує гранульований контроль ролей за принципом найменших привілеїв.

**2.6. Здійсніть огляд Cloud Storage та його ключових функцій.**  

**Google Cloud Storage (GCS)** — це масштабоване, надійне та високопродуктивне об'єктне сховище (Object Storage), призначене для централізованого збереження неструктурованих даних у вигляді об'єктів (Objects), розміщених у бакетах (Buckets).

---

**2.7. Охарактеризуйте різні класи сховищ у GCP: Standard, Nearline, Coldline, Archive.**   

Google Cloud Storage пропонує єдиний уніфікований API для чотирьох класів зберігання даних:

| Клас сховища GCP | Частота доступу та призначення | Мін. термін зберігання | Вартість зберігання / зчитування |
| :--- | :--- | :--- | :--- |
| **Standard Storage** | Часто запитувані дані («гарячі» дані: веб-контент, стримінг, активні бази даних). | Відсутній (0 днів) | Найвища вартість зберігання гігабайта, але найдешевші операції зчитування. |
| **Nearline Storage** | Дані з рідким доступом (не частіше 1 разу на місяць: місячна звітність, резервні копії). | 30 днів | Нижча вартість зберігання, невелика плата за кожен гігабайт зчитаних даних. |
| **Coldline Storage** | Дані з дуже рідким доступом (не частіше 1 разу на квартал чи рік). | 90 днів | Низька вартість зберігання, вища вартість за операції зчитування. |
| **Archive Storage** | Довготривалий архів («холодні» дані: юридичні архіви, регуляторні вимоги). | 365 днів | Найнижча вартість зберігання, але найвища вартість зчитування. |

**2.8. Опишіть, як працювати з Cloud Storage на прикладі використання мови Python або C#.**  

Для програмної взаємодії з об'єктним сховищем Google Cloud Storage у середовищі Python використовується офіційна клієнтська бібліотека **google-cloud-storage**.

```python
import os
from google.cloud import storage

def upload_file_to_gcs():
    os.environ["GOOGLE_APPLICATION_CREDENTIALS"] = "/path/to/service_account_key.json"
    bucket_name = "my-rpz34-cloud-bucket-2026"
    source_file_path = "C:/data/report.pdf"
    destination_blob_name = "reports/2026_report.pdf"

    storage_client = storage.Client()
    bucket = storage_client.bucket(bucket_name)
    blob = bucket.blob(destination_blob_name)
    blob.upload_from_filename(source_file_path)
    print(f"Файл завантажено: {blob.public_url}")
```

#### Файл-довідка з базових команд та синтаксису Google Cloud SDK (gcloud CLI)

* **Загальна архітектура команди:**
  `gcloud <група-сервісів> [підгрупа] <дія/команда> [прапорці та параметри]`
* **Глобальні параметри форматування виводу:**
  * `--format="table(name, zone, status)"` — компактне форматування відповідей у вигляді таблиці;
  * `--format="json"` — вивід даних у структурованому форматі JSON;
  * `--format="yaml"` — вивід у форматі YAML;
  * `--filter="status=RUNNING"` — фільтрація списків за значеннями полів.
* **Базові команди керування автентифікацією та конфігураціями:**
  * `gcloud auth login` — інтерактивна автентифікація користувача через веб-браузер;
  * `gcloud auth list` — перегляд усіх авторизованих облікових записів у консолі;
  * `gcloud config list` — перегляд поточної конфігурації (проєкт, зона, регіон);
  * `gcloud config set project <project-id>` — перемикання активного проєкту GCP;
  * `gcloud config set compute/zone europe-west1-b` — встановлення дефолтної обчислювальної зони.
* **Керування проєктами (GCP Projects):**
  * `gcloud projects list` — перегляд списку доступних проєктів;
  * `gcloud projects create <project-id> --name="My Cloud Lab"` — створення нового проєкту;
  * `gcloud projects delete <project-id>` — видалення проєкту разом зі всіма внутрішніми ресурсами.
* **Керування віртуальними машинами (Google Compute Engine):**
  * `gcloud compute instances list` — перегляд списку віртуальних машин у проєкті;
  * `gcloud compute instances create my-vm --zone=europe-west1-b --machine-type=e2-micro --image-family=ubuntu-2204-lts --image-project=ubuntu-os-cloud` — створення ВМ Ubuntu;
  * `gcloud compute instances start my-vm` — запуск зупиненої віртуальної машини;
  * `gcloud compute instances stop my-vm` — зупинка віртуальної машини (припинення тарифікації vCPU/RAM);
  * `gcloud compute instances delete my-vm` — остаточне видалення інстансу ВМ;
  * `gcloud compute ssh my-vm --zone=europe-west1-b` — захищене SSH-підключення до ВМ через закритий тунель Google.
* **Керування хмарним сховищем (Google Cloud Storage):**
  * `gcloud storage buckets list` — перегляд списку бакетів у проєкті;
  * `gcloud storage buckets create gs://my-unique-bucket-name --location=europe-west1` — створення нового бакета;
  * `gcloud storage cp local-file.txt gs://my-unique-bucket-name/` — завантаження файлу в об'єктне сховище.

### Відповіді на контрольні питання

**1. У чому полягає принцип роботи TOTP-аутентифікації? Наведіть приклади в контексті Google Authenticator і 2-Step Verification.**   

**TOTP (Time-based One-Time Password / Тимчасовий одноразовий пароль)** — це криптографічний алгоритм генерації одноразових динамічних паролів (специфікація RFC 6238), заснований на обчисленні хеш-функції HMAC від комбінації таємного ключа (Shared Secret) та поточного квантованого системного часу (Unix Timestamp, вікно у 30 секунд). Отриманий 6-значний код є дійсним лише протягом пів хвилини, після чого безповоротно змінюється.

**Контекст Google Authenticator та 2-Step Verification:**
* **Синхронізація секрету:** Під час увімкнення 2-Step Verification Google генерує унікальний секретний ключ і відображає його у вигляді QR-коду. Додаток Google Authenticator зчитує цей ключ і зберігає його в захищеному сховищі смартфона.
* **Автономність генерації:** Смартфон із Google Authenticator не потребує підключення до Інтернету або стільникової мережі SMS для обчислення коду, оскільки обчислення виконується локально на основі поточного часу пристрою.
* **Розширені фактори 2-Step Verification:** Окрім класичного TOTP, захист Google 2-Step Verification підтримує сповіщення від Google (Google Prompts / «Торкніться для підтвердження»), електронні фізичні ключі безпеки FIDO2/WebAuthn (YubiKey) та резервні одноразові коди відновлення.

**2. Опишіть формат JSON: де він використовується, які його особливості. Чи застосовується цей формат у GCP?**  

**JSON (JavaScript Object Notation)** — це текстовий формат обміну та серіалізації структурованих даних, заснований на синтаксисі об'єктів JavaScript, але повністю незалежний від конкретних мов програмування. Дані моделюються за допомогою пар «ключ: значення» (об'єкти `{}`) та впорядкованих списків значень (масиви `[]`).

**Ключові особливості формату:**
* Проста текстова структура, зрозуміла людині та легка для парсингу програмами;
* Стандартизована підтримка у всіх сучасних мовах програмування (Python, Java, Go, C#);
* Гнучкість схеми даних для моделювання складних ієрархічних об'єктів.

**Застосування формату JSON у Google Cloud Platform:**
1. **Ключі сервісних акаунтів (Service Account Keys):** Файли облікових даних для автоавтентифікації додатків вивантажуються з GCP у форматі `.json`.
2. **Політики доступу Cloud IAM:** Визначення прав, ролей та умов доступу описується у вигляді структурованих JSON-документів.
3. **Вивід команд gcloud CLI:** Прапорець `--format="json"` повертає повні детальні відповіді будь-яких команд gcloud у форматі JSON.
4. **Взаємодія через GCP REST API:** Усі API-запити та відповіді між клієнтськими SDK та сервісами Google Control/Data Plane передаються у форматі JSON.

**3. Які основні API надає Google Cloud Platform? Коротко охарактеризуйте їх призначення.**  

Google Cloud Platform надає сотні спеціалізованих програмних інтерфейсів API, які розділені за основними категоріями:
1. **Resource Management & Compute APIs (Control Plane APIs):**
   * *Compute Engine API:* управління життєвим циклом віртуальних машин, дисків та мереж;
   * *Kubernetes Engine API:* розгортання та керування кластерами контейнерів Kubernetes (GKE);
   * *App Engine Admin API:* управління версіями та конфігураціями PaaS-додатків.
2. **Storage & Database APIs (Data Plane APIs):**
   * *Cloud Storage API:* завантаження, зчитування та управління об'єктами й бакетами;
   * *BigQuery API:* виконання аналітичних SQL-запитів над надвеликими масивами даних;
   * *Cloud SQL Admin API / Firestore API:* операції з реляційними та NoSQL базами даних.
3. **AI & Machine Learning APIs:**
   * *Vertex AI API, Cloud Vision API, Cloud Translation API:* інтеграція готових моделей штучного інтелекту та комп'ютерного зору в додатки розробників.
4. **Identity & Security APIs:**
   * *IAM API:* управління сервісними акаунтами, ролями та політиками авторизації.

**4. Як можна встановити Google Cloud SDK (CLI) під різними операційними системами?**  

* **Microsoft Windows:**
  1. Завантаження та запуск офіційного інсталятора `GoogleCloudSDKInstaller.exe` з порталу Google Cloud;
  2. За допомогою системного диспетчера пакетів у консолі PowerShell: `winget install Google.CloudSDK`;
  3. Через менеджер пакетів Chocolatey: `choco install gcloudsdk`.
* **Apple macOS:**
  1. Завантаження тарболу `.tar.gz`, його розпакування та запуск скрипта встановлення `./google-cloud-sdk/install.sh`;
  2. Через менеджер Homebrew: `brew install --cask google-cloud-sdk`.
* **GNU/Linux (Ubuntu / Debian):**
  Встановлення з офіційного APT-репозиторію Google Cloud CLI.
