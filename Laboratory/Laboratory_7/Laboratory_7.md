**2.1. Для чого потрібні Azure Marketplace Images? Чим відрізняються готові публічні образи з Azure Marketplace від приватних образів, створених користувачем (Custom Images)?**

**Azure Marketplace Images** — це стандартизовані шаблони (образи) ОС та встановленого програмного забезпечення, вивірені інженерами Microsoft або офіційними сертифікованими вендорами (Canonical, Red Hat, SUSE, Oracle, Cisco) для прискореного створення та деплою віртуальних машин Azure Virtual Machines. **Публічні образи (Marketplace Images) є загальнодоступними системними дистрибутивами (Ubuntu Server, Debian, Red Hat Enterprise Linux, Windows Server 2019/2022/2025), а також передконфігурованими стеками (WordPress, LAMP, SQL Server, Docker, Deep Learning VMs), які доступні всім користувачам платформи за моделлю Pay-as-you-go або з власними ліцензіями (BYOL). Натомість **Приватні образи (Custom Images / Azure Compute Gallery) - це персоналізовані образи, згенеровані розробником або системним адміністратором на основі еталонної віртуальної машини (зроблений sysprep для Windows або waagent -deprovision для Linux). Вони містять власні корпоративні налаштування безпеки, фірмові додатки, внутрішні сертифікати й скрипти, зберігаються у приватному каталозі **Azure Compute Gallery (Shared Image Gallery)** і доступні виключно в межах організації або конкретної підписки Azure.

**2.2. Для чого потрібні Azure Managed Disks? Які типи дисків підтримуються в Azure?**  

**Azure Managed Disks (Керовані диски Azure)** — це віртуальні блокові накопичувачі високої доступності, абстраговані від фізичних систем зберігання даних, які Azure автоматично створює, моніторить та за якими здійснює операції балансування й заміна обладнання. Managed Disks ізолюють користувача від складнощів управління Storage Accounts, гарантують стійкість на рівні 99.999% та підтримують підключення до ВМ «гарячим» способом без зупинки роботи сервера.

**Типи керованих дисків в Azure:**
1. **Ultra Disk Storage:** Надкастомні блокові диски з екстремальною продуктивністю (до 160 000 IOPS та 4000 МБ/с пропускної здатності, затримка sub-millisecond). Використовуються для важких транзакційних СУБД (SAP HANA, Oracle, top-tier SQL Server).
2. **Premium SSD v2:** Нове покоління продуктивних дисків із можливістю гнучкого незалежного конфігурування обсягу, IOPS та Throughput. Ідеально підходять для високонавантажених OLTP-систем та баз даних із мінливим навантаженням.
3. **Premium SSD:** Твердотільні накопичувачі на основі SSD з високою пропускною здатністю для продуктивних серверів розробки, баз даних та серверів додатків.
4. **Standard SSD:** Економічні SSD-диски, які пропонують послідовну та стабільну роботу на низьких затримках для веб-серверів із помірним трафіком, легких баз даних та систем розробки/тестування.
5. **Standard HDD:** Традиційні магнітні жорсткі накопичувачі, що забезпечують найнижчу вартість за гігабайт для рідко запитуваних даних, фонових пакетних запусків та некритичних систем зберігання.

**2.3. Для чого використовуються Snapshots в Azure? У яких випадках їх доцільно використовувати?**  

**Azure Disk Snapshots** — це точкові розряджені копії (Point-in-Time Read-Only Backups) керованих дисків Azure Managed Disks, які зберігаються в автономній інфраструктурі Azure Storage. Вони є інкрементними (зберігають лише блоки, що зазнали змін із часу попереднього знімка), що суттєво заощаджує витрати на дисковий простір. Їх доцільно використовувати під час створення точок відновлення перед виконанням критичних оновлень ядра ОС, встановлення патчів безпеки або масштабного деплою нового релізу програмного коду. Також Snapshots застосовують при швидкій клонованій генерації нових керованих дисків або перетворенні снапшота на власний кастомний образ ОС. Крім того,варто виокремити їх застосування при відновленні працездатності ВМ після атак шкідливого ПЗ (Ransomware), системних помилок чи несанкціонованого видалення даних, а також міграції ресурсів та їх резервування між різними географічними регіонами чи підписками.

**2.4. Перерахуйте основні типи віртуальних машин (VM sizes) у Azure. Коли доцільно використовувати кожен з них?**  

Сервіс **Azure Virtual Machines** пропонує чітку класифікацію серій інстансів під різноманітні профілі навантаження:
* **General Purpose (Загального призначення — B, D-серії):** збалансоване співвідношення vCPU та оперативної пам'яті. **B-серія (Burstable)** ідеальна для робочих навантажень із короткими сплесками активності (мікросервіси, малі веб-сервери, розробка), а **D-серія** призначена для стабільних корпоративних застосунків та середніх СУБД.
* **Compute Optimized (Оптимізовані за обчисленнями — F-серія):** високе співвідношення vCPU до обсягу пам'яті на базі потужних процесорів Intel/AMD. Використовуються для високонавантаженого кодування відео, обчислювального моделювання, ігрових серверів та батч-обробки коду.
* **Memory Optimized (Оптимізовані за пам'яттю — E, M-серії):** високий обсяг RAM на одне процесорне ядро. Необхідні для великих реляційних та NoSQL баз даних (In-Memory Redis, SAP HANA, SQL Server Data Warehouse).
* **Storage Optimized (Оптимізовані за дисковим вводом-виводом — L-серія):** висока пропускна здатність та прямо підключені NVMe-накопичувачі з наднизькою затримкою. Використовуються для Cassandra, MongoDB, Elasticsearch та аналітики великих даних (Big Data).
* **GPU / Accelerated Computing (Прискорені обчислення — N-серія):** оснащені прискорювачами NVIDIA Tensor Core. Застосовуються для глибокого навчання (AI/ML), рендерингу 3D-графіки, штучного інтелекту та віртуалізації робочих столів (VDI).

### Відповіді на контрольні питання

**1. Яку роль відіграють SSH-ключі або паролі при підключенні до Azure Virtual Machine?** <br>

**SSH-ключі (для Linux-інстансів)** забезпечують високонадійну автентифікацію на основі асиметричної криптографії (алгоритми RSA або ED25519). Публічний ключ (Public Key) автоматично імпортується агентом Azure Linux Agent у конфігураційний файл `~/.ssh/authorized_keys` віртуальної машини при її створенні. Приватний ключ (Private Key у форматі `.pem`) зберігається на локальному комп'ютері користувача і використовується для підтвердження особи під час SSH-хендшейку. Це унеможливлює атаки перебором паролів (Brute-Force) та гарантує захищений доступ без передачі секретів через мережу.  
**Паролі (для Windows-інстансів та альтернативного входу Linux)** використовуються як стандартний первинний фактор автентифікації облікового запису системного адміністратора (наприклад, `azureuser` чи `Administrator`). У Windows Server пароль обов'язковий для відкриття інтерфейсу RDP. Для підвищення рівня безпеки паролі повинні відповідати вимогам складності Azure (мінімум 12 символів, наявність великих/малих літер, цифр і спецсимволів) або зберігатися у зашифрованому сховищі **Azure Key Vault**.

---

**2. Яка команда використовується для підключення до Linux-віртуальної машини в Azure через SSH?** <br> 

Стандартний виклик у командному рядку (PowerShell, Bash, Terminal) має наступний синтаксис:
```bash
ssh -i "шлях/до/приватного_ключа.pem" ім'я_користувача@публічна_IP_адреса
```

Розшифровка параметрів:
  * `-i` *(identity file)* — вказує шлях до локального файлу приватного ключа `.pem`;
  * `ім'я_користувача` — системний логін, вказаний при створенні ВМ у порталі Azure (наприклад, `azureuser` або `ubuntu`);
  * `публічна_IP_адреса` — дійсний Public IP віртуальної машини.  

Практичний приклад:
```bash
chmod 400 ~/.ssh/azure_linux_key.pem
ssh -i ~/.ssh/azure_linux_key.pem azureuser@20.238.112.45
```

*(Примітка: команда `chmod 400` у Linux/macOS обмежує права доступу до ключа виключно для власника, що є обов'язковою вимогою клієнта OpenSSH).*

---

**3. Як ще можна підключитися до Linux-віртуальної машини в Azure?** <br>

1. **Azure Serial Console:** прямий текстовий доступ до апаратного послідовного COM-порту віртуальної машини безпосередньо у вікні Azure Portal. Дозволяє відновлювати доступ при збоях мережевих конфігурацій чи помилках у файлі `fstab`.
2. **Azure Bastion:** повністю керований PaaS-сервіс для безпечного підключення за протоколами SSH/RDP безпосередньо через браузер за допомогою TLS (порт 443) без необхідності виділення віртуальній машині публічної IP-адреси.
3. **Azure CLI (`az ssh vm`):** підключення через командний рядок із використанням авторизації Microsoft Entra ID (Azure AD) та короткоживучих OpenSSH-сертифікатів без ручного створення локальних файлів ключів.
4. **Run Command (Azure Guest Agent):** виконання довільних bash-скриптів на віртуальній машині з правами `root` безпосередньо з консолі Azure Portal для оперативного адміністрування чи скидання налаштувань доступу.

---

**4. Як можна підключитися до Windows-віртуальної машини в Azure?** <br>
1. **Remote Desktop Protocol (RDP):** використання штатної програми «Підключення до віддаленого робочого столу» (`mstsc.exe` у Windows чи Microsoft Remote Desktop на macOS/Linux) через відкритий мережевий порт 3389.
2. **Azure Bastion:** графічне підключення до робочого столу Windows Server у вікні браузера через захищене TLS-з'єднання без відкриття порту 3389 у публічну мережу Інтернет.
3. **PowerShell Remoting / WinRM:** віддалене консольне управління сервером через протоколи Windows Remote Management (порти 5985 HTTP або 5986 HTTPS) для виконання автоматизованих скриптів без завантаження графічного інтерфейсу.

---

**5. У чому відмінність між станами Stop (Deallocate) і Delete для віртуальної машини в Azure?** <br>

| Критерій порівняння | **Зупинка з вивільненням: Stop (Deallocate)** | **Остаточне видалення: Delete** |
| :--- | :--- | :--- |
| **Обчислювальні ресурси (vCPU, RAM)** | Повністю вивільняються з фізичного сервера-хоста Azure. | Повністю вивільняються з фізичного сервера-хоста Azure. |
| **Системні диски (Managed Disks)** | Зберігаються у хмарі разом із усіма збереженими даними, конфігураціями та системою. | За замовчуванням видаляються назавжди (або зберігаються окремо за вибором користувача). |
| **Публічна IP-адреса (Public IP)** | Динамічна IP-адреса звільняється; статична IP зберігається за акаунтом. | Повністю видаляється або повертається у глобальний пул адрес Azure. |
| **Можливість відновлення/старту** | ВМ можна запустити повторно (**Start**) у будь-який момент із повним збереженням стану. | Конфігурація ВМ видаляється остаточно без можливості запуску. |
| **Тарифікація та білінг (Billing)** | Плата за процесори та оперативну пам'ять **ПРИПИНЯЄТЬСЯ**; платиться лише невелика сума за зберігання диска Managed Disk. | **Будь-яка тарифікація за ВМ та прив'язані диски повністю припиняється.** |

### Висновки

У ході виконання лабораторної роботи було повністю розібрано теоретичні та практичні засади управління віртуальною інфраструктурою Microsoft Azure, а також здобуто цінний досвід діагностики системних обмежень IaaS-платформи. Детально вивчено призначення Azure Marketplace Images, типів керованих дисків Managed Disks (SSD/HDD/Ultra), знімків дисків Snapshots, а також класифікацію серій віртуальних машин (B, D, F, E, L, N). Здійснено практичне дослідження причин виникнення помилок `SkuNotAvailable` та `Capacity Restrictions`. Встановлено, що безкоштовні та студентські акаунти Azure підлягають жорсткому обмеженню квот на vCPU в популярних регіонах через дефіцит фізичних серверних потужностей B-серії. Опрацьовано та проаналізовано повний спектр команд Azure CLI для розгортання ресурсів (`az group create`, `az vm create`), налаштування мережевих правил, перевірки стану інстансів (`az vm list`), а також коректного завершення роботи (`az vm deallocate`, `az vm delete`).
