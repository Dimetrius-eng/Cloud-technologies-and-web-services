# Лекція 3

## Виконав: Руденко Дмитро, РПЗ-34

### Вставлені пропущені слова у реченнях:

1. Хмарні технології забезпечують **розподілену** обробку даних, надаючи користувачам ресурси через **Інтернет**.   
2. Основними компонентами архітектури хмарних обчислень є **Front end** *(клієнтська частина)*, **Back-end platforms** *(внутрішні платформи)* та **Cloud-based delivery and a network** *(хмарна доставка та мережа)*.  
3. Публічна хмара управляється **третіми** сторонами та пропонує сервіси за моделлю "**pay-as-you-go**" *(оплата по мірі використання)*.  
4. Приватна хмара дозволяє обмежити доступ до **інфраструктури** користувача та забезпечує високий рівень **безпеки**.  
5. Гібридна хмара поєднує можливості **публічної** та **приватної** хмар, що дозволяє масштабувати ресурси за необхідністю.  
6. У моделі "Інфраструктура як послуга" (IaaS) користувач отримує доступ до **процесорів** та **пристроїв для зберігання інформації** для створення власних операційних систем і додатків.  
7. У моделі "Платформа як послуга" (PaaS) користувач може встановлювати власні **додатки**, але не керує **базовою інфраструктурою хмари** *(мережами, серверами, ОС, сховищами)*.  
8. У моделі "Програмне забезпечення як послуга" (SaaS) користувач отримує доступ до **додатків**, що працюють у хмарній **інфраструктурі**.  
9. Хмари спільноти створюються для спільного використання інфраструктури між організаціями з **спільними** цілями *(проблемами або завданнями)*.  
10. Основними перевагами мультихмари є **гнучкість** та можливість уникнути **прив'язки** до одного постачальника *(vendor lock-in)*.

### Порівняльна таблиця моделей розгортання хмар:

| Критерій порівняння | Публічна хмара (Public Cloud) | Приватна хмара (Private Cloud) | Гібридна хмара (Hybrid Cloud) | Мультихмара (Multi-cloud) |
| :--- | :--- | :--- | :--- | :--- |
| **Управління та власність** | Управляється третіми сторонами (хмарними провайдерами) для загального користування. | Контролюється й експлуатується однією організацією у власних інтересах. | Поєднує компоненти публічної та приватної хмар через стандартизовані технології. | Передбачає одночасне використання сервісів від кількох незалежних провайдерів. |
| **Багатокористувацькість (Tenancy)** | **Multi-tenant**: спільне використання інфраструктури багатьма клієнтами. | **Single-tenant**: виділена інфраструктура тільки для одного абонента. | Поєднує виділені приватні та спільні публічні ресурси. | Може комбінувати кілька публічних або приватних середовищ. |
| **Рівень безпеки та контроль** | Базовий/середній; збільшений ризик витоку через спільні ресурси. | **Найвищий**; конфіденційні дані не виходять за межі приватної мережі. | **Високий**; критичні дані зберігаються у приватній частині, інші — в публічній. | **Підвищений**; за рахунок розподілу даних та додатків між провайдерами. |
| **Масштабованість** | Практично необмежена та миттєва під пікові навантаження. | Обмежена потужностями власного заліза та територією розгортання. | **Висока**; дозволяє ефективно долати пікові навантаження завдяки хмарі. | **Максимальна**; вибір найкращих ресурсів у різних провайдерів під конкретні задачі. |
| **Фінансова модель** | **Pay-as-you-go** (без великих початкових інвестицій у залізо). | Високий CapEx/OpEx (витрати на власне залізо, ліцензії та фахівців). | Оптимізовані витрати (дешевше ніж чисто приватна хмара). | Гнучка за рахунок вибору найвигідніших тарифів у різних провайдерів. |
| **Ключові переваги** | Відсутність початкових витрат, простота використання, висока економічність. | Повний контроль, дотримання регуляторних стандартів, захист даних. | Гнучкість, баланс між безпекою та дешевим масштабуванням. | Уникнення прив'язки до провайдера (vendor lock-in), висока відмовостійкість. |
| **Недоліки** | Занепокоєння щодо безпеки, обмежена прозорість інфраструктури. | Високі витрати, обмежена зона доступності, потреба у кваліфікованих фахівцях. | Складність управління та налаштування безпеки між середовищами. | Висока складність інтеграції, сумісності та підвищені витрати на управління. |
| **Приклади рішень** | Amazon EC2, Microsoft Azure, Google Cloud Platform (GCP). | VMware vCloud Suite, OpenStack, Cisco Secure Cloud, HP Helion. | AWS Outposts, Azure Stack, Google Anthos, IBM Cloud Satellite. | Kubernetes, Red Hat OpenShift, Cloud Foundry, Docker Swarm. |
